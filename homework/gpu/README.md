## Часть 1. Теория

### 1. Пять основных блоков видеокарты

1. **GPU (графический процессор)** — выполняет параллельные вычисления, обработку геометрии, пикселей и шейдеров.
2. **VRAM (видеопамять)** — хранит текстуры, буферы кадров, модели и промежуточные данные.
3. **Шина и контроллер памяти** — обеспечивают обмен данными между GPU и VRAM.
4. **Подсистема питания (VRM)** — преобразует и стабилизирует напряжение для GPU и памяти.
5. **Система охлаждения** — отводит тепло от процессора, памяти и силовых компонентов.

Дополнительно видеокарта имеет интерфейс PCI Express и видеовыходы (HDMI/DisplayPort).

### 2. Два архитектурных отличия GPU от CPU

- **Число вычислительных блоков:** CPU имеет относительно немного мощных универсальных ядер, а GPU — много более простых параллельных вычислительных блоков. CPU удобен для последовательной логики и управления программами, GPU — для массовой одинаковой обработки данных.
- **Приоритет архитектуры:** CPU оптимизирован под малые задержки, ветвления и сложное управление; GPU — под высокую суммарную пропускную способность при параллельных вычислениях. Поэтому CPU управляет игрой и её логикой, а GPU обрабатывает множество пикселей и вершин одновременно.

### 3. VRAM и обычная оперативная память

VRAM — локальная память видеокарты, предназначенная для быстрого доступа GPU к текстурам, кадрам и вычислительным данным. Оперативная память компьютера (RAM) в основном обслуживает CPU и программы. Видеопамять стараются делать высокопропускной, поскольку GPU одновременно обрабатывает большие массивы данных: недостаточная скорость памяти ограничивала бы работу вычислительных блоков.

### 4. SIMT и варпы

SIMT (Single Instruction, Multiple Threads) означает, что много потоков выполняют одну инструкцию над разными данными. NVIDIA объединяет потоки в группы — **варпы**, обычно по 32 потока. Это позволяет эффективно выдавать инструкции сразу группе потоков. Если потоки одного варпа идут по разным веткам условия, часть выполнения может сериализоваться, что снижает эффективность.

### 5. Охлаждение и питание

Подсистема питания подаёт GPU и памяти стабильное напряжение при изменении нагрузки. Охлаждение отводит тепло, возникающее при работе. Если охлаждение не справляется, видеокарта обычно снижает частоты (троттлинг), может работать медленнее или аварийно отключиться для защиты оборудования.

## Часть 2. Схема

### 6. Упрощённая блок-схема

```text
    [CPU + системная RAM]
              |
              | команды, ресурсы
              v
        [PCI Express]
              |
              v
  +--------------------------- ВИДЕОКАРТА ---------------------------+
  |                                                                  |
  |  [Подсистема питания / VRM] ---> [GPU]                           |
  |                                   ^  |                           |
  |                                   |  |                           |
  |                            [Контроллер/шина памяти]              |
  |                                   ^  |                           |
  |                                   |  v                           |
  |                                [VRAM]                            |
  |                                                                  |
  |  [Охлаждение] -- отвод тепла от GPU, памяти и VRM                 |
  |                                                                  |
  |  [GPU] ---> [Контроллер вывода] ---> [HDMI / DisplayPort] --------+---> [Монитор]
  +------------------------------------------------------------------+
```

CPU готовит команды и передаёт их видеокарте через PCIe. GPU использует VRAM через шину памяти, формирует изображение, после чего готовый кадр передаётся через контроллер вывода и видеопорт на монитор. Питание и охлаждение обеспечивают работу, но не являются частью потока графических данных.

## Часть 3. Практика

### 7. Характеристики видеокарты

Для **настольной NVIDIA GeForce RTX 3060 12 GB**:

| Характеристика | Значение |
|---|---|
| Модель | NVIDIA GeForce RTX 3060 (desktop, 12 GB) |
| Объём VRAM | 12 ГБ |
| Тип видеопамяти | GDDR6 |
| Ширина шины | 192 бит |
| CUDA-ядер | 3584 |
| Типичное энергопотребление видеокарты (TGP) | 170 Вт |
| Эффективная скорость памяти | 15 Гбит/с на контакт |
| Паспортная пропускная способность | 360 ГБ/с |

*Примечание:* TGP 170 Вт — показатель энергопотребления видеокарты, который часто приводят вместо TDP. Точные параметры следует сверить для конкретной модификации.

### 8. Расчёт пропускной способности памяти

Для GDDR6 используется **эффективная** скорость передачи данных 15 Гбит/с на контакт (эквивалент 15 000 Мбит/с на контакт). Ширина шины — 192 бита.

```text
Пропускная способность = 15 000 × 192 / 8
                       = 360 000 МБ/с
                       = 360 ГБ/с
```

Результат **360 ГБ/с** совпадает с паспортной пропускной способностью настольной RTX 3060 12 GB. Важно не подставлять физическую частоту памяти вместо эффективной скорости передачи без учёта особенностей GDDR6.

### 9. Что происходит при запуске игры

1. Пользователь запускает игру, операционная система загружает программу и необходимые данные в оперативную память.
2. **CPU** выполняет игровую логику: обрабатывает ввод, физику, положение объектов и команды движку.
3. Драйвер и графический API помогают подготовить команды для **GPU**; нужные текстуры и другие ресурсы передаются в **VRAM**.
4. **GPU** выполняет обработку геометрии, шейдеров, освещения и пикселей, читая данные из VRAM и записывая результаты в буферы кадров.
5. Готовый кадр поступает к подсистеме вывода изображения.
6. Через HDMI или DisplayPort сигнал передаётся на монитор, который показывает изображение. Цикл повторяется для следующих кадров.

## Часть 4. Вывод

### 10. Почему GPU полезны для искусственного интеллекта

GPU умеет одновременно выполнять множество похожих математических операций над большими массивами чисел. В нейросетях часто используются матричные умножения, которые хорошо распараллеливаются. Высокая пропускная способность видеопамяти помогает быстро подавать данные вычислительным блокам. Поэтому GPU ускоряет обучение и применение многих моделей искусственного интеллекта по сравнению с выполнением тех же операций только на CPU.
