# UEFI/BIOS и диагностика загрузки

## Как загружается ПК

1. После включения прошивка инициализирует процессор, память и устройства. На этом этапе выполняется POST. Если плата останавливается с индикатором DRAM, сначала проверяю память по руководству к плате.
2. В режиме Legacy BIOS прошивка передаёт управление загрузочному коду первого сектора выбранного диска. В типичной установке Windows в режиме UEFI используется диск GPT с системным разделом EFI (ESP, FAT32).
3. Менеджер загрузки UEFI выбирает запись из `BootOrder`. Запись `BootNext` задаёт приоритет на один запуск. Запись загрузки указывает на устройство и EFI-программу, например `\\EFI\\Microsoft\\Boot\\bootmgfw.efi`. Для съёмного накопителя на x86-64 стандартный путь — `\\EFI\\BOOT\\BOOTX64.EFI`.
4. Загрузчик запускает ядро ОС. Если появилось меню GRUB или экран Windows Boot Manager, прошивка уже нашла и запустила загрузчик. Дальше проверяю конфигурацию загрузчика и ОС.
5. При включённом Secure Boot прошивка проверяет, разрешён ли запуск EFI-образа. Сообщение о недопустимой подписи означает, что нужно проверить источник и совместимость образа.

## Где остановилась загрузка

| Симптом | Первая проверка | Следующий шаг |
|---|---|---|
| Чёрный экран, индикатор DRAM остаётся включён | Вход монитора, кабель, индикаторы диагностики по инструкции платы | При выключенном и обесточенном ПК проверить посадку памяти. Если нужно, проверить один модуль в рекомендованном слоте. |
| UEFI открывается, SSD отсутствует в списке накопителей | Проверить раздел NVMe/SATA в меню прошивки, совместимость слота и диск | Для SATA проверить оба кабеля при выключенном ПК. Для M.2 сверить тип накопителя и поддерживаемые интерфейсы слота. |
| SSD виден, но Windows Boot Manager отсутствует | Проверить режим загрузки и наличие ESP | Загрузиться с установочной флешки в режиме UEFI. В режиме восстановления проверить, читаются ли раздел и установка Windows. |
| После подключения флешки запускается установщик вместо ОС | Проверить, какой пункт выбран в меню загрузки | Для разового запуска выбрать нужный пункт через Boot Menu. Для обычного запуска поставить Windows Boot Manager первым. |
| Security Violation при запуске с флешки | Проверить, соответствует ли образ архитектуре ПК и доверен ли его загрузчик | Пересоздать флешку из официального образа и выбрать её UEFI-запись. |
| Появилось меню GRUB, но Linux останавливается в initramfs | Записать текст ошибки и проверить, видна ли корневая файловая система | Из среды восстановления сверить UUID разделов с настройками загрузчика и `fstab`. |

## Учебный пример диагностики

Исходная ситуация: в UEFI виден NVMe SSD, но после включения выводится «No bootable device». В меню загрузки нет Windows Boot Manager. С загрузочной флешки я проверяю, что она запущена в режиме UEFI. В среде восстановления сначала выполняю только проверку:

```text
diskpart
list disk
list volume
exit
```

В `list disk` звёздочка в столбце GPT показывает тип таблицы разделов. В списке томов ищу небольшой раздел FAT32 и проверяю, что папка Windows читается. Буквы в среде восстановления могут отличаться от букв в установленной системе.

Если диск GPT, раздел EFI и установка Windows читаются, вероятная причина — отсутствующая запись загрузки либо повреждённые файлы на ESP. Тогда имеет смысл запустить восстановление при загрузке. Если понадобится BCDBoot, перед его использованием сверяю путь к установленной Windows и проверяю, что выбран ESP нужного диска. После восстановления извлекаю флешку и проверяю, загружается ли Windows Boot Manager.

На Linux с доступной средой восстановления можно уточнить, в каком режиме загружена сама среда, и посмотреть устройства и записи загрузки:

```bash
test -d /sys/firmware/efi && echo UEFI || echo "Режим без UEFI"
lsblk -o NAME,SIZE,FSTYPE,PARTTYPENAME,MOUNTPOINTS
efibootmgr -v
```

Последняя команда показывает записи NVRAM при загрузке в UEFI и наличии утилиты. Если установленная система запускается хотя бы до ядра, дополнительную информацию дают сообщения загрузчика и журнал, например `journalctl -b -p err` для текущей загрузки.

## Вывод

Последний видимый этап помогает сузить поиск. Отсутствие POST ведёт к проверке оборудования. Отсутствие записи загрузки при видимом диске ведёт к проверке ESP и режима прошивки. Ошибка после запуска загрузчика ведёт к проверке самого загрузчика, ядра и раздела ОС. Пример разобран теоретически, без изменения настроек реального ПК.
